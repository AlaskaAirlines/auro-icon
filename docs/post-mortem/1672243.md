# AB#1672243

## Executive Summary

When an icon can't be found, for example because its name is misspelled, auro-icon shows a stand-in error icon instead of leaving an empty gap. That stand-in was an older error icon that the Auro icon library has marked for removal. It now uses the library's current error icon, an outlined triangle with an exclamation mark. Missing airline tail logos still show the default tail logo. Nothing else about the component changes.

Ticket: [AB#1672243](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1672243). It shipped in PR #287 alongside AB#1668022.

## The Problem

auro-icon's stand-in for missing icons was an icon the icon library had deprecated. It looked different from the error icon used elsewhere in Auro, and once the library removes it, auro-icon would stop building.

## Root Cause

- `src/baseIcon.js` imported `@alaskaairux/icons/dist/icons/alert/error.mjs` and used it in `firstUpdated()` as the fallback for any icon that didn't load and whose name doesn't start with `tail-`.
- In `@alaskaairux/icons` 5.30.0, `alert/error.svg` carries `data-deprecated="true"`. Its replacement, `alert/error-stroke.svg`, isn't deprecated.
- `test/auro-icon.test.js` imported the same deprecated icon for the three generic-fallback tests, so the tests pinned the deprecated look.

## The Fix

One commit, `fix: replace the deprecated error fallback icon with error-stroke`:

- `src/baseIcon.js` imports `alert/error-stroke.mjs` as `errorStroke` and uses `errorStroke.svg` for the non-tail fallback. The `tail-` branch still uses `logos/tail-DEFAULT`.
- `test/auro-icon.test.js` imports `error-stroke.mjs` for the three generic-fallback tests: no name, a missing name in `logos`, and a non-tail icon that fails to load. Biome reformatted the longer `parseFromString(...)` calls. The tail fallback test is unchanged.

## Why This Works

- **The tests catch the old icon.** Run against the old `src/baseIcon.js`, the three updated tests fail. With the fix, all 28 tests pass.
- **No dependency change was needed.** `error-stroke` ships in the installed `@alaskaairux/icons` 5.30.0. The ticket said 5.23.0, but this branch had already bumped it.
- **Screen reader behavior is unchanged.** Neither icon hides itself, and auro-icon's wrapper keeps the fallback hidden by default. A browser check of the Fallback example showed `aria-hidden="true"` on the wrapper, with the new description, "triangle with exclamation mark.", in place of "Error alert indicator.".
- **The docs stay accurate.** They describe the fallback as "an error icon" without naming or showing a specific one, so no copy changed.

## Outcome

- Missing icons show Auro's current outlined error triangle, matching the rest of the design system.
- auro-icon no longer depends on an icon scheduled for removal, so the next icon-library cleanup won't break its build.
- Missing airline tail logos still show the default tail logo.
- `npm run build` passes `auro cem-check --strict`, lint is clean, and all 28 tests pass.

## Learnings

- **Check fallback assets for deprecation too.** The examples' `pin-trip` and this fallback icon were both deprecated in the icon library without anyone noticing. Searching `@alaskaairux/icons` for `data-deprecated="true"` against every icon the component imports or shows would catch both.
- **Prove a test catches the change.** Running the updated tests against the old source showed the three fallback tests fail there, so the tests guard the new icon instead of just matching whatever the code imports.
- **Call out visual swaps for consumers.** Teams that snapshot the fallback SVG, or check for `error__desc` or "Error alert indicator.", will see a difference after upgrading. The release notes should mention it.
