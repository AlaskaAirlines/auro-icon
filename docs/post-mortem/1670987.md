# AB#1670987

## Executive Summary

auro-icon and auro-alaska only read their settings when they first appear on the page, so later changes were ignored. A team could switch an icon, or show an icon to screen readers, and nothing would happen. Both components now update right away when those settings change. This fixes the new docs site's Icon playground, which showed an error icon. It also fixes alert icons that stayed stale when the alert's type changed, and icons that screen readers announced with no name after being revealed. Nothing that works today changes.

Ticket: [AB#1670987](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1670987). It shipped in PR #287 alongside AB#1668022 and AB#1672243.

## The Problem

Teams change icons while a page is running. A dropdown arrow is meant to flip, an alert switches its icon with its type, and the docs site playground changes the icon as you type. auro-icon ignored all of those changes, so it showed the wrong icon, or an error icon. An icon that started hidden from screen readers and was revealed later was announced as an image with no name. auro-alaska had the same problem with its tagline setting.

## Root Cause

- `BaseIcon.firstUpdated()` in `src/baseIcon.js` was the only place an icon was loaded. It fetched `category` and `name` once, after the first render. Later changes to either, or to `customSvg`, re-rendered the element but never fetched again.
- `AuroIcon.firstUpdated()` in `src/auro-icon.js` removed the SVG's `<desc>` and `aria-labelledby` **from the loaded SVG itself** when `ariahidden` wasn't `"false"`. Exposing the icon later updated the wrapper's `aria-hidden` but couldn't bring the description back, so screen readers found an unnamed image.
- `AuroAlaska.firstUpdated()` in `src/auro-alaska.js` picked its artwork once, and only ever set its private `alaska` flag to `false`, so turning `official` on or off later did nothing.
- When the element was created before its attributes were set, as the docs site playground does, the first load requested `icons/undefined/undefined.svg`.

## The Fix

One commit, `fix: update icons when their properties change after first render`:

- **Same pattern as other Auro components.** `firstUpdated()` stays and still does the initial load. A new `updated(changedProperties)` handles later changes, as auro-tail, dialog, dropdown and input do. `willUpdate` wasn't needed.
- **`src/baseIcon.js`**
  - The body of `firstUpdated()` moved into `loadIcon()`, which `firstUpdated()` calls.
  - `loadIcon()` numbers each call and keeps only the latest call's result, so a slow earlier response can't replace a newer icon.
  - It skips the request when `category` or `name` is missing and shows the error fallback directly.
  - It keeps the loaded SVG as `_sourceSvg` and shows `prepareSvg(_sourceSvg)`.
- **`src/auro-icon.js`**
  - The description stripping moved into a `prepareSvg()` override that works on a **clone**, so the loaded SVG keeps its description.
  - `updated()` skips the first cycle, which `firstUpdated` already handles. After that, it calls `loadIcon()` when `name`, `category` or `customSvg` changes, and re-applies `prepareSvg()` when `ariaHidden` changes.
- **`src/auro-alaska.js`**
  - The artwork choice moved into `pickArtwork()`, which sets `alaska = !official` both ways.
  - `updated()` calls it again when `official` changes.
- **Docs:** removed every "doesn't currently …" caveat about first-render-only properties that AB#1668022 had added: `name`, `category`, `customSvg`, `ariaHidden`, `official`, and the ARIA hidden guide. The resize limit stays, because `<auro-alaska>` still measures its width only when it renders.
- **Tests:** seven new WTR tests:
  - changing `name`;
  - changing `category`;
  - attributes set after creation, with no `undefined` request;
  - out-of-order responses;
  - `customSvg` turned off;
  - `ariahidden` toggled both ways;
  - `official` toggled both ways.

## Why This Works

- **The tests catch the bug.** All seven fail against the old source, and pass with the fix. The full suite of 35 passes, and so does the existing request-deduplication test.
- **Nothing that works today changes.** The first load still runs from `firstUpdated`, and a missing name still shows the error icon, just without the bad request. `updated()` only acts after the first render, so the first render doesn't fetch twice.
- **It works in a real browser.** With the bundle in headless Chrome:
  - changing `name` swapped the icon;
  - attributes set after creation showed the requested icon;
  - toggling `ariahidden` to `"false"` took the accessibility tree from nothing to `img "drop pin with circles."`;
  - toggling `official` switched the logo artwork.
- **It works on the docs site.** On the docs site MVP, the Icon playground now renders `pin-trip-filled` instead of the error icon, and follows the `name` control.
- **`connectedCallback` wasn't enough.** It runs only when the element is added to the page, so it can't react to changes while the icon stays on the page.

## Outcome

- Icons update when teams change which icon to show, use their own graphic, or reveal an icon to screen readers.
- The docs site's Icon playground works with no extra changes on the docs site.
- Screen reader users hear an icon's description when a team reveals it, instead of an unnamed image.
- The Alaska Airlines logo switches between its plain and tagline versions when that option changes.
- auro-alert's stale icon and auro-input's workaround are fixed once those packages update to this version of auro-icon.
- The build passes `auro cem-check --strict`, lint is clean, and all 35 tests pass.

## Learnings

- **Follow the repo family's lifecycle pattern.** Most Auro components keep `firstUpdated` for setup and add `updated(changedProperties)` for changes. Checking that before planning kept the fix small and familiar to reviewers.
- **Keep the original, render a copy.** Changing a loaded asset in place, by stripping its description, made the change impossible to undo later. Keep the source and derive what's shown from it.
- **Guard async loads against reordering.** Any property that triggers a fetch can change faster than the network responds. A per-call counter is enough to keep the newest result.
- **Test in the real consumer.** The unit tests passed, but running the docs site playground found the `undefined/undefined.svg` request the acceptance criteria rule out.
- **A playground fires a request on every keystroke.** Typing a name requests every partial name, and `cacheFetch` caches each 404 until the page reloads. That belongs to the playground and `cacheFetch`, not this fix, but it's worth knowing.

## Iterations That Didn't Work

- **Moving the initial load out of `firstUpdated` and using `willUpdate`.** The first plan did both. The lead's review pointed out that almost no Auro component does either; `willUpdate` appears in only 3 of about 48. The fix kept `firstUpdated` and used only `updated()`, at the cost of one extra render when `ariahidden` changes.
- **`connectedCallback`.** Considered at the lead's suggestion and rejected, because it doesn't run when properties change while the icon is on the page.
- **Loading on change without checking for missing attributes.** The first version fixed the playground's icon but still requested `undefined/undefined.svg` on the first render. The docs site check caught it, and `loadIcon()` now skips the request when `category` or `name` is missing.
