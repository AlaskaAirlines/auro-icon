# AB#1668022

## Executive Summary

auro-icon now publishes the machine-readable description of what it offers (its custom-elements manifest), and every build checks that description against Auro's strictest automated rules. Code editors, AI assistants and Auro tools can now offer autocomplete, inline help and warnings for `<auro-icon>` and `<auro-alaska>`. All of the component's help text was rewritten in the plain voice of Auro's content guidelines and checked against how the component actually behaves. That check found several statements that were wrong, and an accessibility bug behind one of them, which is now fixed. Nothing was renamed or removed. Two rounds of lead review on the pull request found more gaps, all of which are now fixed or settled with the lead.

Ticket: [AB#1668022](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1668022). This is auro-icon's share of AB#1667039.

## The Problem

auro-icon's published package didn't include its component description file, so tools that rely on it got nothing, and the public link to the file returned "not found". The component's help text was also out of date and inconsistent with other Auro components, and some of it described behavior the component doesn't have.

## Root Cause

- **Packaging.** `package.json` pointed `customElements` at `custom-elements.json`, but the file wasn't listed in `files` or `exports`. So `npm publish` left it out, and unpkg returned 404. A stray top-level `"custom-elements.json"` key did nothing.
- **No gate.** The repo was on `@aurodesignsystem/auro-cli` `^3.6.0`, which predates `auro cem-check`, so nothing validated the manifest.
- **JSDoc that didn't match the contract.** The baseline `auro cem-check --strict` run reported 11 warnings:
  - `attribute-name-not-lowercase` for `onDark`, `customColor`, `customSvg` and `ariaHidden`. These were declared without an explicit `attribute:`, so the manifest recorded the camelCase property name.
  - `deprecated-prose-unflagged` for `onDark`, which said "DEPRECATED" in prose but had no `@deprecated` tag, on both elements.
  - `enumerated-union` for `appearance`, documented with `@property {...}` instead of `@type`, so the manifest typed it as bare `string`.
- **A bug fixed along the way: `ariaHidden="false"` produced an unnamed image.** `firstUpdated` in `src/auro-icon.js` stripped the SVG's `<desc>` and `aria-labelledby` whenever `hasAttribute("ariaHidden")` was true, which it is for any value. So `ariaHidden="false"` exposed the graphic to screen readers and removed its name in the same step. A browser probe confirmed it:
  - `"false"` gave `aria-hidden=false` with no description;
  - `"true"` gave `aria-hidden=true` with no description;
  - unset gave `aria-hidden=true` with the description kept.
- **Help text never checked against the code.** The descriptions said:
  - `customSvg` renders into the default slot. It renders the `svg` slot.
  - `customColor` "applies the primary color selector". It makes the icon inherit the surrounding text color.
  - `ariaHidden="false"` lets screen readers "announce the content from the SVG's title". It didn't; see "A bug fixed along the way" below.
  - `<auro-alaska>` is "auto-aware" of its container size. It picks its artwork once, in `firstUpdated`.
- **Claims that survived the first rewrite.** The first `/auro:doc-review` run found two more inaccurate statements in the new docs:
  - Under `appearance="inverse"`, the docs said only `disabled`, `muted` and `statusError` change color and the other variants fall back to the default inverse color. In `color.scss`, `:host(:not([onDark])[variant="accent1"])` has specificity (0,3,0) and beats `:host([appearance="inverse"])` at (0,2,0), so the other variants keep their light-background colors.
  - The `<auro-alaska>` slot was described as the way to name the logo, and the example put "Alaska Airlines" in it. The logo SVG already has `role="img"` and `aria-labelledby` pointing at its own title and description, so its name is "Alaska Airlines Logo image for Alaska Airlines". Slot text made screen readers announce the name twice.
- **A published helper and a base class weren't documented to the guidelines.** The manifest publishes `cacheFetch` from `src/cacheFetch.js`, but its parameters had no descriptions, and the nested `@param … [options.responseParser=(response) => response.text()]` leaked into the `options` type text, because the CEM analyzer doesn't parse nested option params. `BaseIcon` documented a default slot even though it has no `render()`, and both subclasses inherited that slot entry in the manifest.
- **The documented defaults never ran.** `BaseIcon._initializeDefaults()` sets `onDark = false` and `appearance = "default"`, but `AuroIcon` and `AuroAlaska` override it without calling `super`. So both properties read `undefined` at runtime while the manifest documented `false` and `"default"`. `/auro:code-review` raised this.
- **`demo/alaska.md` had no generator.** It feeds the "Alaska Logo" tab on the Auro docs site, which imports it from the published package. The auro-cli migration removed `packageScripts/processDocs.mjs`, which used to build it from `docs/partials/alaska.md`. auro-cli only builds `index.md` and `api.md` from partials, so the file had become a hand-kept copy, kept in git by a `!demo/alaska.md` exception in `.gitignore`.
- **Gaps the PR review found.** The lead's review of PR #287, which included a fresh `/auro:doc-review` run, found:
  - `@aurodesignsystem/auro-config` was still `^1.3.1`. Version 1.3.2 makes the release config recognize the `!` breaking-change marker, which semver governance relies on.
  - `onDark` and `official` carried `@default false`. A Boolean property that defaults to `false` doesn't need the tag.
  - The `cacheFetch` `options` description didn't say that only the first call for a URL uses its `responseParser`. Later calls get the cached promise.
  - The `appearance-inverse.html` captions were lowercase, and the `fallback.html` markup comments were in title case.
  - `docs/partials/index.md` had drifted from the auro-templates `index.md`: two headings weren't in sentence case, and the top comment used a spaced em dash.
- **Gaps the second review found.** The lead's second review found:
  - The docs said `ariaHidden="false"` makes screen readers announce the icon's built-in description, but not every icon has one. In `@alaskaairux/icons` 5.30.0, 59 of 374 icons have no `<desc>` and hide themselves with `aria-hidden="true"`, including `in-flight/wifi`, which an example uses. The same claim was in the ARIA hidden guide and the `firstUpdated` comment.
  - `docs/partials/customRegistration.md` used the passive voice.
  - The docs didn't say how a custom SVG gets its size. The component's `svg` sizing rule doesn't reach a slotted SVG, and every example sized it inline. A browser check showed that an SVG with a `viewBox` and no `width` or `height` fills `--ds-auro-icon-size` on its own, while one with its own size or no `viewBox` overflows the icon.
  - `basic.html`, `custom.html` and `custom-size.html` showed icons with no description, although the docs say to describe meaningful icons.
  - Most examples, the class example and the README used `interface/pin-trip`, which the icon library marks as deprecated.
  - Nothing in the API docs linked to the list of available icons.

## Why This Works

- **Lowercase attribute names change no behavior.** HTML lowercases attribute names when it parses markup, and Lit already lowercased these names at runtime. Attribute selectors such as `:host([onDark])` match case-insensitively on HTML elements. The new test "binds camelCase and lowercase attribute spellings to the same properties" pins this. The other two new tests check styling: `ondark` matches `appearance="inverse"`, and `customcolor` inherits the parent's color.
- **The gate covers publishing, not only PRs.** auro-icon's PR and release workflows both call the shared `auro-actions/.github/actions/build`, which runs `npm ci` and then `npm run build`. A cem-check failure therefore fails the PR and blocks the publish.
- **The shipped artifact was checked, not just `src/`.** `npm pack --dry-run` lists `custom-elements.json` (32.8 kB) and `demo/alaska.md`. The generated `dist/index.d.ts` was diffed against the published 9.2.0 package.
- **Moving the alaska demo source needs no docs site change.** The review asked whether the docs site would need updating. AuroDocsSite reads the page from npm, not from git: `src/content/dynamic/icon/alaska.js` imports `@aurodesignsystem/auro-icon/demo/alaska.md`, which resolves through the package's `"./demo/*.md"` export. The build still writes `demo/alaska.md`, and the PR's preview package (`0.0.0-pr287.4`), built after the file stopped being tracked, includes it. auro-dialog already works this way: the docs site imports its `demo/*.md` pages from npm, and auro-dialog gitignores them.
- **The `ariaHidden` default stays where it is.** Moving `ariaHidden = "true"` into the constructor would reflect the attribute and trigger the `hasAttribute("ariaHidden")` branch in `firstUpdated` on every icon. That would strip every icon's description, a behavior change. So the effective default is described in prose instead.
- **The generated alaska page was checked in a browser.** The local dev server serves the generated `demo/alaska.md`. Headless Chrome rendered all five sections and all 12 logos, with no page errors, and the auto-scale rows picked the expected artwork at 72, 108, 192 and 528 px. The text matches the old hand-kept copy; only code-block markup differs, now matching `demo/api.md`.
- **The defaults fix changes no rendering.** `appearance` now reflects `appearance="default"` onto the host, matching auro-button. No selector in `src/styles` keys on that value, and the styling tests still pass. `onDark = false` doesn't reflect an attribute.
- **Dropping `@default false` changes only the docs.** `_initializeDefaults()` still sets `onDark` and `official` to `false`, so runtime behavior is the same. `auro cem-check --strict` stays clean without the tag.
- **The `ariaHidden` fix only changes the case that was broken.** Unset and `"true"` behave exactly as before. Only `"false"` changes, from an unnamed image to one that announces its built-in description, which is what the docs always promised. None of the local Auro repos set `ariaHidden="false"` on `auro-icon`. auro-dropdown sets `ariaHidden="true"`, which is unaffected.

## Learnings

- **A content pass is also a bug hunt.** Checking the `ariaHidden` docs against the code exposed a real accessibility bug. `hasAttribute()` on a string-valued attribute is true for `"false"` too; compare the value instead.
- **`ariaHidden` also shadows the native `Element.ariaHidden`.** The property maps to the `ariahidden` attribute, not `aria-hidden`, which confuses consumers who use the ARIA reflection API. Renaming it is a breaking change, so it's tracked separately as AB#1669750. Making icons update after the first render isn't breaking and caused visible bugs, so it was split into AB#1670987 and fixed in this same PR.
- **auro-cli 5's type generator drops `@private` properties.** `alaska` on `<auro-alaska>` was private and undocumented, but the 3.x types exposed it in the JSX props. It no longer appears. It was never public API, but a TypeScript consumer passing `alaska` in JSX would now see a type error.
- **Check prose against the code before trusting the manifest.** cem-check validates the shape of the manifest, not whether it's true. Four of the corrected statements passed every automated check.
- **Lowercase `attribute:` names are safe whenever Lit already derived them.** Lit lowercases property names to get attribute names by default, so an explicit lowercase name changes only the manifest. Confirm that the styles use attribute selectors, which match case-insensitively on HTML elements, rather than JavaScript string comparisons.
- **A dependency major bump can be checked by byte-comparing the build.** Saving `dist/` before the bump and running `cmp` after it showed that design-tokens 9 and webcorestylesheets 12 change nothing auro-icon ships.
- **Check which demo files the build actually generates.** auro-cli builds `demo/index.md` and `demo/api.md` from `docs/partials`, and every file in `docs/pages/` into `demo/`. Anything else under `demo/` that's tracked in git is hand-kept and can drift. Search the docs site for imports from the package's `demo/` folder before deciding a file is unused.
- **Verify cascade claims against selector specificity, not rule order.** A `:host(:not([a])[b])` rule outranks a later `:host([c])` rule, so "this mode overrides that variant" needs checking in the browser or by specificity.
- **Check what an SVG already announces before documenting a label slot.** The Alaska logos carry their own `role="img"` and title, so a label slot adds to the name rather than providing it.
- **`/auro:doc-review` doesn't cover `docs/pages/*.md`.** Its doc-source patterns are `src/**` JSDoc, `docs/partials/*.md`, `apiExamples/*.html` and README text, so `docs/pages/alaska.md` is out of its scope after the move. Its content was reviewed in the first run, while it was still a partial. Raise this with auro-ai so the skill can add the pattern.
- **Doc-review only covers files the branch changed.** `cacheFetch` is published in the manifest, but `src/cacheFetch.js` wasn't touched, so the skill skipped it. Check the manifest's module list for published helpers and base classes before calling a content pass complete.
- **A clean doc-review run isn't the final word.** The branch's runs came back clean, and the lead's run still found five findings, including an inaccurate claim. A follow-up run then found two more inaccurate claims, and the doc-review pass in `/auro:code-review` found three passive phrases that standalone runs had passed. After the second review, two full re-reads found ten more passive or "you can" phrases in items earlier runs had only skimmed. Runs differ in what they catch, so run it again after each round of fixes, and expect the reviewer's run to find more.
- **Don't assume every library icon has a description.** 59 of the 374 icons in `@alaskaairux/icons` 5.30.0 have no `<desc>` and hide themselves. Check the icon library before describing what a whole category of icons does.
- **Slotted content doesn't get the component's styles.** The `svg` sizing rule in the shadow root doesn't reach a slotted SVG. A browser check settled what the docs needed to say; reading the code alone couldn't.
- **Check examples for deprecated icons.** Readers copy examples as written, and `pin-trip` had been marked deprecated in the icon library without anyone noticing. The docs site lists deprecated icons on its own page.
- **The CEM analyzer drops some JSDoc.** It doesn't parse nested `options.x` params, which leak into the parent's type text, so describe an options object with an inline type such as `{ responseParser?: ResponseParser }`. It also never emits `@returns` descriptions: auro-button's manifest has none of 18. Keep the descriptions in source for editors and readers anyway.
- **`@relevantWhen` and `@requiredWhen` only work on properties and slots.** Sun raised this for `@cssprop` in her response on her CEM PR. auro-cli's CEM config reads the inline form only in `@slot` descriptions and the block tag only on properties. Before you apply a review suggestion that adds one of these tags, check that the tag is supported where it would go.
- **Leave `@default false` off Boolean properties.** Lit already treats an unset Boolean as `false`, so the tag adds nothing. auro-button's `onDark` still carries it, so don't treat the button PR as the complete reference for doc conventions.
- **Keep `@aurodesignsystem/auro-config` current.** Semver governance depends on its release config. 1.3.2 is the first version that recognizes the `!` breaking-change marker.
- **Extra demo pages belong in `docs/pages/`.** auro-cli has fixed source paths for `index.md` and `api.md` in `docs/partials/`, and builds every other page from `docs/pages/`. auro-hyperlink uses the same split. The generated `demo/*.md` files then behave the same way: built, gitignored and shipped.
- **Shared headings can be synced, not just reported.** The guidelines say not to edit shared template headings in a component, to avoid drift. When the component is the one that has drifted and the template already has the new wording, syncing to the template serves that rule.
- **Wait for nested elements, not just the fixture.** "customcolor inherits the surrounding text color" failed once. `fixture()` resolved when its wrapper `<div>` rendered, and the test read the icons' computed colors before they had rendered. Awaiting each icon's `updateComplete` fixed it.
- **Check how a value behaves when it changes, not just its initial state.** Several properties were only read on the first render. Each claim was true for initial markup, so it passed review until a pass asked what happens when the value changes later.
- **Run both review skills: they catch different things.** `/auro:doc-review` checks wording against the guidelines. `/auro:code-review` found the defaults bug and the incomplete logo name, which doc-review had passed. Each review round produced fixes the other had missed.
- **`npm run lint` failed on `dev`** with formatting and import-order errors that lint-staged didn't fix. They were fixed here in a formatting-only commit. A local `.claude/settings.local.json` still trips biome on your own machine, because biome only reads the repo's `.gitignore`. CI doesn't have that file.

## Iterations That Didn't Work

- **Running the work in a sandboxed shell.** Every write failed, including `$TMPDIR`, the repo and `~/.npm`, so the first attempt couldn't install, build or test. The work resumed once commands were allowed to run outside the sandbox.
- **Using `git` and `npm pack` inside the sandbox.** `.git/FETCH_HEAD` and the scratch directory weren't writable. The API snapshot went to the gitignored `.cache/` directory instead.
- **Documenting `responseParser` as a nested `@param`.** Even without the arrow-function default, a separate `@param {ResponseParser} [options.responseParser]` line still leaked into the `options` type text. Folding it into an inline type, `{ responseParser?: ResponseParser }`, fixed it.
- **A hyphenated `@returns {…} - …` to get return descriptions into the manifest.** The analyzer drops `@returns` descriptions in either form, so the change was reverted.
- **Moving `alaska.md` back next to `index.md` and `api.md` in `docs/partials/`.** This was considered so that every demo source would sit in one folder, but auro-cli only reads those two pages from partials. Without a custom build script nothing would generate `demo/alaska.md`, so it stays in `docs/pages/`.
